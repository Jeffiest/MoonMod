# Delivery roadmap

## 0. Shared framework foundation

- Publish a package format and versioned cross-game API map.
- Both game adapters now emit an explicit supported/unsupported capability record for every non-core operation; startup rejects incomplete ledgers and unsupported operations without reasons. The headless report validates per-domain and overall catalog totals and fails if the verification matrix omits or duplicates a catalog domain.
- Build the local package manager, dependency/status reporting, profiles, declared settings, and isolated mod storage.
- Embed Lua and protect each script with memory and instruction budgets.
- Add a two-pane manager to each PC port and launch it from PC settings.
- Emit lifecycle/tick hooks and expose a common core API. Both ports publish a game-filtered `game.events.list()` catalog (30 Chronicle events / 33 Chronicle Two events), including manager `ui.action`; native contracts verify every listed event can be subscribed and unsubscribed, and retail Lua fixtures verify the catalog in each executable. Owner-scoped Lua exports also support list/call/unregister with declared-dependency visibility; both adapter contracts and the Chronicle executable preflight exercise discovery and invocation.

## 1. Port adapters

- Add scene, map, dungeon/floor, save, pause, input, and UI lifecycle events at verified native boundaries. World locations are sampled immediately after each initialized scene and still polled per frame for transitions inside a scene; finer event timing at every native floor/map loader remains open.
- Expose stable read APIs for game state, then safe mutation calls, with phase constraints and ownership handles. Both ports now return generation-checked monster handles through `entities.get` and spawn owned registered enemies. Chronicle loads package-owned models into a free slot in its native nine-model floor table; ChronicleTwo loads inherited or mod-owned model resources through its native manager. Both ports expose `entities.despawn`, which removes owned live enemies through per-actor native cleanup, invalidates handles, and updates alive counts without kill credit or drops. Safe live actors are also removed when their Lua mod unloads. Chronicle rejects mimics because their map chest trigger retains a native reference; ChronicleTwo rejects actors held by native interactions. Arbitrary NPC/object kinds remain open.
- Chronicle's `party.set_active` validates joined status, health, active dungeon context, current action locks, restricted zones, and Osmond's ground restriction before invoking its native character-and-weapon reload routine. ChronicleTwo uses its native quick-change eligibility path and townsperson recruitment. Chronicle NPC recruitment remains unsupported because its save model has no separate companion roster.
- Add transaction-backed content registries for items, characters, enemies, dialogue, effects, recipes, maps, dungeon graphs, georama pieces, skill trees and UI entries.
- Both games' `characters.register` operations add namespaced enemy variants to their native monster-definition resolvers, and both support package-owned model bindings through `models.register`. Chronicle variants inherit template effects and drops while overriding HP, defense, and rewards; ChronicleTwo also supports attack changes. Each port's retail-data headless test copies a retail model pack to a new virtual path, registers it on an enemy, spawns that enemy, and confirms the custom path is loaded on the live floor. Chronicle's loader consumes a free slot in its nine-model floor table and can reject a spawn when that table is full or not initialized. Both games return generation-checked handles readable through `entities.get`; synthetic tests cover registration ownership, handle reuse, unavailable templates or inactive dungeons, explicit despawn, and unload cleanup. Newly authored model/rig validation, custom AI behavior, and localized mod enemy names remain open.
- ChronicleTwo's `dungeons.register` can add connected rooms to one of the seven native dungeon maps, choose native exit/boss/side-room flags and Monica/Max seals, and verify materialized metadata; `world.register_dungeon` remains a compatibility alias. Mod floor progress now uses stable package IDs in a versioned sidecar keyed to the unchanged native save payload, allowing additions beyond each dungeon's fixed retail floor-record allocation. `dungeons.list/get` expose additions and pending/registered floor IDs. Independent dungeon maps, scripts, geometry and room assets remain open.
- Both games expose guarded `content.unregister`. Chronicle removes character variants only after checking child variants, model bindings, registered dungeon floors, loaded floor models, and tracked actor handles; item, weapon, and dungeon definitions remain because their native slots are persistent. Chronicle Two removes pending items, weapons, dungeon additions, and Georama piece variants before native materialization, while rejecting materialized records and character variants.
- Chronicle's `dungeons.register` and `world.register_dungeon` append procedural floors to native dungeons 0-4, copy a selected existing normal/back-side enemy layout into each new slot, and update the native floor count used by progression, entrance selection, Atla distribution, and last-floor indicators. `dungeons.list/get` report native dungeons plus registered extensions, with stable mod floor IDs and native slot numbers. Tests cover chained source-floor copies, both enemy-layout tables, the compatibility alias, catalog lookup, invalid source rejection, and the 25-floor save/table boundary. Optional `enemies` arrays replace the encounter with up to nine same-mod registered characters in both native layout tables; the retail headless character probe registers and enters Sentinel Depths floor 15 with a custom model-backed enemy. Floor names remain metadata while the game displays numeric floors; custom geometry, map identities, assets, and standalone dungeon graphs remain open.
- Both games expose `physics.query` as a bounded sphere query over live monster actor origins, returning generation-checked handles, positions, and distances. It does not claim collider, wall, floor-geometry, or line-of-sight results. Chronicle's `physics.velocity_get` reports live enemy movement intent from its native direction/speed or knockback fields, including frozen and falling states; `physics.velocity_set` writes that intent and native AI may replace it on a later step. Native collision-geometry queries and broader spatial object types remain open.
- Chronicle's `locations.list/get` reads all 16 native world-map destinations, including built-in IDs, frames, map IDs, and save-backed visit/dungeon progress; `world.transition` queues built-in settlement routes from active town/dungeon scenes. ChronicleTwo's `locations.list/get` reads the localized native `map/map*.cfg` catalog, including native map IDs/types, titles, areas, and selection categories. Its `locations.register` appends a namespaced standalone interior-map row after native rows, requires package-owned `.map` and `.cfg` scripts plus either package-owned `.mpk`/`.ipk` packs or a native `texture_source_map` for pack reuse, pins package overrides for the session, and `world.transition` can queue that destination from active town/dungeon scenes. `texture_source_map` can supply native `.mpk`/`.ipk` files when a package omits those packs and maps embedded texture provenance to a compatible native map's converted catalog entries. Retail headless verification edits one `MAP_PARTS` position in a copied shop-map script, loads it through `CScene` at appended index 189, captures the interior scene, and uses a separate run to return to native Georama town map 0. This verifies loading/rendering of a modified compatible copy and return flow, not wholly authored map assets. Native adapter and texture-source tests cover the mapping, while executable Lua smoke covers asset ownership, list/get, index preservation, entry, return, and inactive-scene guards. New map formats, full authored map validation, and Georama settlement registration remain open.
- Chronicle's `locations.register` adds a namespaced location identity by aliasing one of ten reserved `gedit/s60`–`gedit/s69` map directories to the indexed assets for a built-in field map. Package-owned overrides can replace individual files such as `mapinfo.cfg`; aliases and their overrides stay pinned until process exit because the native loader cannot safely unregister them. Chronicle native tests cover registration, catalog lookup, alias-backed reads, entry, and return. The retail-data Lua probe verifies a copied `s13` field script through assigned map ID 70 and its return to Norune. This is compatible-copy support; wholly authored field assets and new world-map frame/table registrations remain open.
- Native file readers on both PC ports resolve owner-scoped `resources.override/unoverride` replacements for indexed paths and bounded new monster `.chr`/`.stb` paths. Chronicle Two also reads explicitly registered, unindexed native map assets (`.cfg`, `.efp`, `.ipk`, `.map`, `.mpk`, `.sky`, `.stb`) under `map/`, with a 3 MiB post-sector-padding cap and data-reader tests for path/extension/size rejection. Map asset overrides used by a registered native location stay pinned until process exit because the native catalog cannot safely remove rows. Package traversal/symlink checks, replacement-size bounds, collision ownership, unload cleanup, and native data-reader tests cover the loader path. `models.resolve` reads both native monster tables and reports `.chr` paths and override state. Both ports' `models.register` bind package assets to native-backed character definitions; `models.unregister` removes unused logical bindings while retaining their independently owned resource overrides. `models.replace/remove` replace or restore a native monster-table model binding with owner checks and active-floor guards; native tests and executable probes cover lifecycle and reference guards. The character probes reuse retail geometry, so authored model format/rig validation remains open. Newly authored map format validation remains open; a compatible copied map already passed retail scene-load, rendering, and return-trip checks.
- Complete authored map support by verifying native file/script formats for non-copied content and making malformed assets fail with clear diagnostics. Compatible copied layouts can now omit copied `.mpk`/`.ipk` packs and inherit them from a native source map; retail entry, rendering, and return-to-town pass for this path. Wholly authored geometry and pack formats remain open.
- Defer authored model formats, rig validation, standalone animation authoring, animation API expansion, and fighting-style definitions until model-rigging work is in scope. Existing model-embedded motion registration/playback and its passing tests remain a frozen baseline; do not expand that area during the current roadmap. Fighting-style APIs remain explicitly unsupported.
- Data-only consumables now register through Lua in both games and have native headless gameplay proofs for HP healing, water restoration, individual status cures, and combined `cure_all` items. Chronicle preserves its 11 persisted legacy item-slot assignments and discovers additional genuinely unused native rows; retail verification registers 12 simultaneous items and confirms the twelfth uses row 142. Exact extra-row capacity and native localization for mod names remain open. Chronicle Two also supports cures for poison, slow, stop, curse, stone, and thirst plus a native timed power-status item; other native item effect families remain open.
- Add stable compatibility/capability queries for Chronicle and Chronicle Two.

## 2. Full creator API

- Chronicle now registers up to 32 data-only Georama variants in appended native definition slots 24–55, without changing the retail save record layout. Variants inherit a loaded native solid template's model, collision, footprint, and placement behavior; stable IDs persist to the local MoonFactory content registry, and unregister is blocked while any town layout still refers to a piece. Native iteration, frame updates, materialization, and placement/save/remove paths cover the extension range. Synthetic adapter coverage checks registration, stable slots, sparse-slot menu enumeration, reference-safe unregister, and native placement/readback/removal. The retail-data headless Lua probe exercises registration plus native placement, saved-layout readback, removal, and disappearance in an isolated save. Native menu text/icons still inherit the template, visual persistence after reload is unverified, and authored geometry/assets remain open.

- Expand player, party, world, entity, combat, script, inventory, weapon, quest, save, input contexts/priority stacks, rendering, physics, resources, and UI APIs. Both ports expose processed left/right stick and analog trigger axes with deterministic headless coverage, mod-owned LIFO input contexts with action-state gating and unload cleanup, read/write velocity for live generation-checked enemy handles, and bounded `render.camera_set` orbit controls alongside the active dungeon camera snapshot. The camera setter changes distance, height, and target angle only while a supported dungeon camera is active; Chronicle Two applies its native distance/height limits and retains collision correction in player-controlled mode. Per-port native adapter tests cover normal and player-controlled camera updates, bounds, and rejection outside a supported dungeon camera; a retail-data Lua smoke also adjusts the live Chronicle Two dungeon camera. Chronicle maps velocity writes to its native direction/speed and knockback fields; the retail headless probe verifies velocity read/write round-trips and bounded sphere queries over live monster origins. Native story flag, integer counter, and map flag get/set calls expose bounded per-game save state for quest interoperability. Chronicle can select an owned compatible weapon from a town-safe saved loadout path; both ports publish equip events for quest objectives. Chronicle also exposes and sets its native water gauge through `player.get/set`, and `player.get` now returns the active native world position during dungeon play on both games. Bounded owner-scoped HUD text layers now use the native presenter; arbitrary draw callbacks and world-space layers still need renderer lifecycle and scene-safety work. Extend physics to native collision geometry and other spatial object types only where movement and collision ownership can be preserved. Extend audio from package playback to native bank replacement and game sound-event hooks.
- Both ports expose generation-checked `combat.damage` and `combat.heal` for live enemies using the same `entity_id` handle returned by `combat.get` or `entities.query`. ChronicleTwo retains its former slot-based heal form for existing mods. Chronicle routes hit/death results through its native monster step and floor kill accounting; ChronicleTwo routes them through native damage/death requests and checks native damage blocks. Scripted kills do not credit a player weapon; collision side effects and reward attribution remain open. Owner-scoped damage formulas are implemented and verified for scripted damage, while the native hit calculations also call the shared registry. Fighting styles and expanded animation/model-rigging work stay paused.
- The shared runtime supports mod-owned skill trees, prerequisites, and persisted ranks, and each in-game manager displays tree nodes, ranks, prerequisites, descriptions, and supported per-rank enemy-damage effects. Bounded `effects.enemy_damage_per_rank` bonuses now apply through both scripted damage and the native enemy-hit calculation; native retail probes verify a skill rank increases damage and resetting the rank removes the bonus. Game-specific skill UI integration remains open. Both games expose native saved Georama state; Chronicle's active-editor `georama.element_set` toggles defined plot elements while honoring element dependencies and updating live/save state. Chronicle also places and removes existing native plot pieces through `SetMapParts` and `DeleteMapParts`, with native stock, fit, collision, fixed-piece, and dependency checks; it now adds data-only variants in slots 24–55, retaining the native save record size and stable IDs. Chronicle's retail Georama probe registers a variant and round-trips it through native placement, save readback, removal, and readback in an isolated save. Template UI text and icons, visual persistence after reload, custom geometry/assets, and player-save compatibility remain unverified. Native and Lua quest tests verify changed-state events. ChronicleTwo's read API decodes saved river-grid dimensions, positions, and cell flags, and its active-scene `georama.river_set` updates existing cells through native neighbor-shaping and save routines. Changed river writes publish deferred events and a Lua quest probe verifies them. Both games can set completion for existing native Georama requests; Chronicle Two also exposes bounded setters for analysis conditions and request-knowledge bytes. Request completion changes prerequisite conditions through the native request setter and reports the resulting town progress. Changed writes publish deferred, idempotent events, and quest probes verify request completion and discovery. Chronicle Two registers data-only piece variants by inheriting loaded native templates and can place and remove solid pieces through native edit, collision, stock, dependency, house, and persistence routines; quest probes verify both deferred events. Creating new river grids, request rewards, and new geometry/assets remain open. The catalog reports unsupported authored locations, wholly new dungeons, and fighting-style operations precisely.
- Chronicle Two's `-RetailGeoramaSmoke` now verifies the full data-only Georama round trip against retail data: a startup Lua mod registers a Rock-based variant before Sindain loads, discovers native floor anchors, places it through the native collision and stock rules, reads it back from the saved town layout, removes it, and confirms it is gone. The disposable-save smoke does not verify menu rendering, visual persistence after process reload, authored geometry, or compatibility with player saves.
- Quest definitions, objective progress, lifecycle events, and persistent state are implemented in the shared runtime on both ports. Objectives can auto-advance from matching `game.*` events, verified for dungeon entry, return-to-town scenes, world location changes, deferred successful item-use events, native weapon upgrades on both games, changed story flag/counter/map-flag writes, changed native Georama request/condition/request-knowledge writes, Chronicle Two active-party switches, companion recruitment, and mod-owned enemy spawn and defeat events. Chronicle publishes confirmed scripted and combat deaths; Chronicle Two publishes accepted lethal `combat.damage` requests or native death-program dispatches and deduplicates its later dead-state opcode. Retail Lua probes require a filtered quest for a newly registered enemy to progress from spawn through defeat on the same generation-checked entity on both games. The in-game mod manager shows per-mod quest progress and provides a two-pane Journal tab that aggregates quests across enabled and disabled packages on both ports, with four visible objective rows and scrollable overflow. Declarative currency rewards (1–32767 Gilda), stable-id item rewards (1–999 per entry), and stable-id weapon rewards (one weapon per entry) support up to eight combined rewards and call their native economy, item, or weapon APIs when completion is committed. API contracts verify schema bounds, reward visibility, boolean and integer weapon-grant result handling, and the `game.write` permission gate; retail-data probes on both games verify the distinct registered weapon reaches native inventory. Partial or failed payouts are surfaced in `quests.completed` and are not retried; process interruption between quest completion persistence and payout can lose a reward. Entries in the games' original journal systems, named flag catalogs, and broader native gameplay event coverage remain open.
- Both PC runtimes queue `game.item_given` after successful `items.give` and `weapons.give` results and `game.item_removed` after successful `items.remove` results. Chronicle Two also emits `game.item_picked_up` after native dungeon item, key, or stolen-item pickups add inventory; its retail-data item smoke injects a built-in pickup and requires a filtered quest to complete from that native event. Chronicle native pickups and inventory removals performed through either game's own menus remain open.
- Localized text catalogs, generated per-mod settings pages, package status/error diagnostics, and versioned save migrations are implemented. Manager enable/disable persists the profile and reloads enabled packages in dependency order; native tests on both ports verify a dependent function caller works again after its provider is toggled off and on. File watching, targeted reloads, and rollback after a package fails during reload remain open.
- Native SDK ABI v1 has package-bound dynamic loading, fingerprinted local trust, game-thread host services, unload cleanup, and permission-checked routing for JSON-callable core APIs through the owning Lua runtime on both ports. The shared-library fixture verifies Lua function discovery and invocation and confirms nested `api.call` is unavailable to native plugins. Callback-based Lua registrations still require native host equivalents; Linux/macOS build and loader verification remain open.
- Add a build/platform matrix and selected stable hook points for trusted native extensions.
- Signature-system APIs are now catalogued and bound per game. Chronicle exposes `player.thirst_get/thirst_set`, active-floor `georama.atla_list/atla_collect`, request-derived `georama.satisfaction_get`, and `dungeons.back_floor_get/enter` with a queued native transition that never consumes the gate key. Chronicle Two exposes `photos.ideas_list/idea_unlock/scoops_list`, `inventions.list/register/craft`, `player.ridepod_get/set`, `player.transform_get/set`, and `dungeons.spheda_get/spawn`. New events are `game.player.thirst_changed`, `game.photo.taken`, `game.invention.created`, and `game.spheda.completed`. Native adapter tests cover state reads/writes, clamping, native save paths, inventory/material rules, and API plus native event payloads. Remaining limits: mod invention recipes are API-visible but are not added to the native invention menu's fixed recipe table; Chronicle satisfaction is derived from native request completion because retail has no separate satisfaction statistic; Chronicle Two's Spheda spawn requires an already allocated floor session; and the Spheda completion event cannot report strokes or medals because the native save stores only the clear flag. Retail-data gameplay proofs for these signature systems remain open.

## 3. Content pipeline bridge

- The local bridge inventories mod manifests, script directives, allocated symbols, file/directory asset hashes, dependencies, and target fingerprints. The [current upstream `v0.1.0` release](https://github.com/fakegenie/DC2-Toolkit/releases/tag/v0.1.0) Windows tool was downloaded to a temporary directory and matched its published archive SHA-256. Using the user's PAL ISO, `dc2tk setup` generated 1,398 scripts and 1,097 libraries without changing the ISO; full retail `dc2tk verify` passed all four stages for all 1,398 scripts. The report notes 227 native-call numbers without registered names. The Calculator example passed static inventory, disc-backed `mod check` (5 scripts compiled, 0 failed), and 3 offline logic tests; the bridge then built a new ISO and the rebuilt image passed all four stages for all 1,398 scripts. The rebuilt source contains 45 assembly-block functions, and the same 227 unregistered native-call numbers remain. The bridge now records the exact launcher file SHA-256; see [`c2script-calculator-pal-build-20261016.json`](../artifacts/c2script-calculator-pal-build-20261016.json), [`dc2tk-verify-pal-v0.1.0-20261016.json`](../artifacts/dc2tk-verify-pal-v0.1.0-20261016.json), and [`dc2tk-verify-calculator-built-pal-v0.1.0-20261016.json`](../artifacts/dc2tk-verify-calculator-built-pal-v0.1.0-20261016.json). These ISO results remain build-only and do not prove that the patched assets load in the PC runtime. The local legacy Python tool suite also passes 170 tests with one skipped; its separate long all-script round-trip was stopped before producing a result.
- Track the conversion boundary, target IDs, asset provenance, local-data requirements, and independent runtime/build verification in [`CHRONICLETWO_SCRIPT_BRIDGE.md`](CHRONICLETWO_SCRIPT_BRIDGE.md).
- Define a shared package resource format only for artifacts the current PC data layer can load safely.
- Keep build-time script patches separately identified, versioned and conflict-checked.

## Release gates

- Both render adapters now expose bounded owner-scoped HUD text layers through their native presenter. Native tests and retail headless Lua probes cover registration, updates, owner-checked removal, and visible text. Arbitrary draw callbacks, textured/shaped layers, and world-space rendering remain open.

- Current capability debt from [`artifacts/verification-report.json`](../artifacts/verification-report.json): Chronicle reports 21 unsupported operations and Chronicle Two 14. The active scene event-program runner is exposed as `native.event.run`; other script VM families remain unsupported. Four `combat.styles_*` operations per game remain paused until model rigging is in scope; preserve existing embedded-motion playback at its verified baseline. Other gaps are Chronicle's `party.recruit`, `georama.request_known_set`, `georama.condition_set`, `georama.river_set`, the `photos.*` and `inventions.*` domains, ridepod/monster-badge operations, and Spheda operations, plus Chronicle Two's `georama.element_set`, `georama.atla_*`, `georama.satisfaction_get`, `player.thirst_*`, and `dungeons.back_floor_*`. Chronicle's `georama.request_set` is supported. `scripts.call_function` and `scripts.list_functions` provide mod-to-mod Lua calls, while `scripts.call` executes the active native event program from its owned override callback.

No API domain is marked stable until game-specific support and unsupported-feature reporting are explicit. Verified slices now include event-driven quest objectives and currency, item, and single-weapon rewards; native journal presentation and recovery after interrupted payouts remain open. Assetless item paths, data-only weapons and enemies, callable mod functions, and skill progression have adapter and headless coverage where reported supported, while each still has separate content or UI limits. ChronicleTwo's location registration has native adapter tests, executable Lua catalog/transition-guard coverage, and a retail-data scene-load/render/return-trip proof for compatible copied maps; newly authored map formats remain open. Other gaps include authored locations, wholly new dungeon graphs, Chronicle native pickup events, Georama geometry, game-specific skill UI, and authored model data. Existing embedded model-motion playback on mod-spawned enemies has native and retail headless proof on both games and remains frozen at that baseline. Further animation API work, standalone animation authoring, and fighting-style authoring are deferred until model rigging is in scope. The two games can implement different capability sets under the same namespace, and mods must query those capabilities before use. Native ABI major versions and package format schema versions are independent from Lua API majors.

Chronicle's location registration has native adapter coverage and a retail-data Lua proof for a copied field alias, map entry, and return to a native settlement. Both ports still need independent proofs for fully authored location assets and routes.

## 4. Modern mod rewrites (ported from legacy windows branch)

- **`moonmod.dungeon-plus`** (2.1): per-floor tiers 0-5 picked on the floor list (`[` `]`, or the gamepad), presets and mutators, a bounty and streaks per floor, a bestiary and trophies, champions (bigger, tougher enemies that drop the legacy dungeon loot), clear rewards, harder enemy AI, and the DarkCloud-Expanded weapon and shop data. Exports `current_tier` and `enemy_bonus` to other mods.
- **`moonmod.adventurer`** (Ascension 3.0; replaces Ascension 1.6 and the Weapon Mastery migration and imports their saved progress): each character levels up on their own to 40, with max HP, damage and a 17-node skill tree in three branches (Might, Vitality, Focus). Spent points unlock Shockwave, Second Wind and Berserk, cast with L2 + Square / Triangle / Circle (F4-F6 on keyboard) and paid with a Focus bar. Also crits, weapon mastery, loot rolls, thirst and durability refunds, and the DarkCloud-Expanded weapon abilities.
- **`moonmod.hub`**, **`moonmod.controls`**, **`moonmod.autosave`**, **`moonmod.expanded-town`**: hotkeys for the skill page (K, or L1+R1+R3) and the journal (J); party controls in town; autosave; a free town camera.
- **Exit gate replacement (not done)**: a walk-through exit room with a stair to the next floor and a stair back to town. The Chronicle patch has an unfinished version, switched off; the earlier seamless mode is also off because it forced the next floor.
