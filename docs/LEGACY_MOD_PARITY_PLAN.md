# Windows mod suite parity plan

> 2026-10-18: Ascension 1.6 and the Weapon Mastery migration described below were replaced by Ascension 3.0 (`moonmod.adventurer`), which imported their saved progress; on 2026-10-19 that package was replaced in turn by RPG: Character Paths (`mods/moonmod.rpg`, see `mods/README.md`). This plan is kept as the record of the legacy-parity work.

Scope: migrate the useful gameplay and presentation features from `Jeffiest/Chronicle`'s `windows` branch into MoonFactory's current Chronicle integration. Exclude test-only packages and co-op/network packages. Keep feature presentation inside the existing MoonFactory Mod Manager, including its Skills, Actions, Quests, and Journal views.

Source inventory checked against `Jeffiest/Chronicle` branch `windows` at tree commit `50c29fcc288619b1a1a24192d1fe4ef12c06046a`: 17 gameplay/UI packages are in scope (`ascension`, `autosave`, `controls`, `dungeon_feats`, `dungeon_plus`, `enemy_variety`, `expanded_abilities`, `expanded_data`, `expanded_town`, `floor_bounty`, `floor_mutators`, `harder_ai`, `hub`, `mod_settings`, `native_menu`, `sturdy`, and `weapon_mastery`). Excluded are `coop` and the disabled test fixtures `data_test`, `engine_test`, `files_test`, and `net_test`. `combat_demo` and `regen_example` are disabled examples, not additional suite features; the regeneration example overlaps Ascension's Regeneration skill.

## Room-to-content population scaling (implemented in source)

Added from the user's large, mostly empty floor screenshot, population density is a required part of this parity pass. Dungeon+ defaults to 1.5–3 monsters and 0.75–1.5 regular chests per **realized** room. The native generator derives separate deterministic density rolls from the generated floor seed, multiplies the selected ratio by `room_num` after layout generation, applies the active additive monster/chest bonus once to that room-derived target, rounds up, and takes the maximum of it and the correspondingly modified native target. This keeps Ascension's count bonuses meaningful on room-heavy floors while never double-applying them. Re-entering the same seed retains its target even if unrelated RNG calls change; changing a configured room count that the generator failed to realize does not inflate spawn targets. The mod never lowers the game's required population. The unmodified target is 15 monsters on the regular-floor path, 8 on the back-floor path, and a random 4–7 regular chests before modifiers. On a large layout, the room-derived target can exceed what the game can place: monster placement is clipped to `MONSTOR_SLOT_MAX - 1`, and regular chests are capped at 48 to reserve 16 of 64 physical box slots for mimics/special boxes. The PC event table has 384 entries, enough for the expanded 64 boxes, 256 actor slots, and Atla events with headroom. Actor placement remains capped at 255. These capacities apply to the PC port; retail array sizes are unchanged.

The four ratios are exposed as Dungeon+ manager settings. Defaults are 150–300% monsters per realized room and 75–150% regular chests per realized room. For example, a generated 20-room floor requests 30–60 monsters and 15–30 regular chests before additive bonuses, then retains whichever target is larger: the room-derived target or the native baseline; each path receives the active bonus exactly once. Dungeon+'s **Room Population Status** manager action reads Chronicle's active additive bonuses and reports realized rooms, effective native minimums, bonus-adjusted room-derived target ranges, and the 255-monster/48-regular-chest target caps. It labels these as targets and warns that limited valid positions can make actual placements fall short; it does not yet read back final placement counts. The setting-change handler immediately reapplies the bounded room ratios and survival chance to Chronicle's generation API; entering a tiered layout reapplies the same settings after room layout is selected. The PC map stores 64 physical boxes (16 reserved for mimics/special boxes) and 384 shared event records; retail capacities are unchanged. The API is mod-owned and is removed on package unload. The player-facing minimum controls are clamped so maximum values cannot fall below minimum values. This implements the requested rule that room count drives both monster and chest density, while preserving the native minimum required for each floor type and disclosing the practical caps. The attached example highlights why room count alone is not enough: the floor should populate proportionally instead of scaling rooms without scaling their contents.

These values are target counts, not a guarantee that every spawn attempt succeeds: the placement search can exhaust valid positions, especially on event-heavy or awkwardly shaped layouts. The manager reports requested target ranges, additive-bonus-adjusted native baselines, and storage caps; it does not yet read back final placed counts. Static source acceptance is complete, while actual placement rates, chest opening, mimics, and Atla behavior remain runtime checks. No build or game test has been run.

Acceptance criteria for this feature: a generated floor's target scales with its actual room count; each generated target is at least the unmodified game's target; same-seed targets are deterministic; min/max settings are bounded and cannot invert; setting the feature to zero leaves the native target unchanged; no placement exceeds native storage; and a very large floor reports the cap rather than silently implying every requested chest was placed. Source paths are present in `ps2/src/monstorunit.cpp` (`ArrangementPos`) and `ps2/src/dungeonmap.cpp` (`buildEventData`), with manager defaults in `mods/moonmod.dungeon-plus/mod.json` and application/status action in `mods/moonmod.dungeon-plus/main.lua`. Static source review confirms the PC capacity expansion is integrated; remaining acceptance is deferred runtime confirmation of event-heavy floors, chest opening, mimics, and Atla events.

## Implementation notes and remaining runtime checks

The intended relationship is one deterministic target per generated floor: monsters = realized rooms × a seeded ratio in the configured 1.5–3.0 default band; regular chests = realized rooms × a seeded ratio in the configured 0.75–1.5 default band. Round upward, preserve the native minimum for the selected floor type, then clip only at a reported, audited capacity limit. The current implementation compares the room target against the native random 4–7 regular-chest baseline and the existing monster target, and reports 255 monster/48 regular-chest-target capacities. The PC arrays now provide 64 physical box slots, 384 shared events, and a 48 regular-chest target, while preserving retail arrays on non-PC builds. The target leaves 16 physical box slots for mimics/special boxes and gives the 256-slot actor table plus Atla events room in the event table. Acceptance still requires runtime confirmation that event-heavy layouts, chest opening, mimics, and Atla events behave correctly; no build or game test has been run.
